Detail circuits WHAT THE CODE ASSUMES

LDR divider

+3V3 ── LDR ──┬──► IO17 / IO16 (ADC)
              │
         R_F ═╪═ 100 nF
              │
             GND

Node voltage rises with light: V = 3.3 · R_F / (R_F + R_LDR), so R_LDR = R_F · (3300 / V_mV − 1). If your board has the LDR on the GND side instead, set LDR_HIGH_SIDE = false in app_config.h.

Balance used by the demo: D = (L − R) / (L + R). D > 0 means the light is on the left.

Stepper drive

Half-step, 8 phases: 1000 1100 0100 0110 0010 0011 0001 1001. 4096 half-steps per output turn nominal (4075.8 on 63.68:1 gearboxes). Keep each half-step ≥ 1 ms or it stalls.

Assumes a 2500 mAh cell, about 85 % boost efficiency and the 3.3 V LDO fed from the 5 V rail. The firmware turns the coils off 300 ms after each move, which is the single biggest saving.

Adding the mystery peripherals

  1. Analog sensor: IO4, IO5, IO1, IO2 (ADC1, keeps working with Wi-Fi).
  2. I²C sensor: same bus as the OLED (IO8/IO9). Run i in the console to see its address.
  3. UART, SPI, PWM, servo, buttons: any free pin; the S3 routes these peripherals to any GPIO.
  4. 5 V devices: power from +5V_MOT, but level-shift or divide any 5 V signal coming back into a GPIO.
  5. Add the pin to board_pins.h first, then use the constant in code.

Before you power it up CAVEATS

LDRs sit on ADC2

IO16 and IO17 return errors or noise once Wi-Fi starts. Keep the radio off, or jumper the LDR signals to IO1/IO2/IO4/IO5 if you need telemetry over Wi-Fi.

IO46 is a boot strap

Use it as an output or a button to GND. A pull-up or a sensor that drives it high at reset can stop the board booting or uploading.

Upload goes through the CP210x

Install the Silicon Labs VCP driver and use a data cable. If auto-reset fails, hold BOOT, tap RESET, release BOOT, upload again.

Motor noise on the sensors

Read the LDRs after the motor stops. Stepping injects noise on the 5 V and ground return, and the cells lag about 30 ms.
